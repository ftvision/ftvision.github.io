# Blog Writing Workflow

This workflow turns a loose idea into a published essay and distribution package.
It is designed for essays about AI agents, product judgment, software work, and
career reflection.

## Default Loop

```text
Capture -> Thesis -> Angle -> Outline -> Draft -> Structural Edit -> Line Edit -> Package -> Distribute -> Learn
```

Use this as a production checklist, not a rigid template. Some short posts can
skip stages, but flagship essays should pass through all of them.

## Stages

### 0. Capture

Collect raw material before it disappears: a product mistake, work observation,
story, quote, disagreement, tweet, article, or half-formed claim.

Output: one raw note that says, "this is about X, but really about Y."

### 1. Thesis

Turn the note into a claim with friction. The thesis should be specific enough
that a smart reader could disagree with it.

Output:

- one central thesis
- one strongest counterargument
- one reason this is specifically worth writing from Feitong's perspective

### 2. Angle

Choose the form of the piece. The same thesis can become a personal story,
industry argument, tactical guide, product teardown, or career reflection.

Output:

- target reader
- angle statement
- essay promise
- primary language

### 3. Outline

Build the skeleton before prose. Every section needs a job.

Output:

```text
Title
Subtitle
Opening scene
Thesis
Section 1
Section 2
Section 3
Counterargument
Conclusion
```

### 4. Draft

Write the ugly complete version without polishing too early.

Output: full draft from beginning to end.

### 5. Structural Edit

Fix the essay before fixing sentences. Check whether the opening earns
attention, the sections follow a clear spine, and the strongest material appears
early enough.

Output: revised section order and specific rewrite instructions.

### 6. Line Edit

Make the prose sharper while preserving the author's voice.

Check for:

- vague abstraction
- weak transitions
- claims without evidence
- English that sounds slightly translated
- overlong setup
- generic AI commentary
- fake profundity

Output: polished essay.

### 7. Package

Make the essay legible before someone clicks.

Output:

- final title
- subtitle or description
- frontmatter
- topics and type
- opening excerpt
- related essays
- Start Here placement, if flagship

### 8. Distribute

Turn one essay into native distribution pieces.

Output:

- one LinkedIn post
- three to five X posts
- optional X thread
- optional Chinese adaptation
- newsletter intro
- quote-card line
- follow-up question for discussion

### 9. Learn

Read the reaction and decide what it means. Separate vanity metrics from real
signals such as thoughtful replies, private messages, saves, reposts by credible
readers, and repeated misunderstandings.

Output:

- what resonated
- what confused readers
- follow-up essay ideas
- updated thesis backlog

## Where Codex Helps Most

The highest-leverage collaboration stages are:

- Thesis: attack and sharpen the claim.
- Angle: pick the version most worth writing.
- Outline: make every section do a job.
- Structural Edit: repair the essay's spine before line editing.
- Distribution: convert the essay into platform-native posts.

Line editing matters, but thesis and structure usually decide whether the essay
is worth reading.

## Operating Rule

Do not start by asking, "What should I write today?"

Start with:

```text
What did I notice that a serious builder would care about?
What is the non-obvious claim?
Why can only I write this version?
```
