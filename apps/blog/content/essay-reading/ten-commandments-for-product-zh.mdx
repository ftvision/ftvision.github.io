### 1. 你要诚实面对：你究竟是 committed to the product，还是只是爱上了这个 idea。

做产品意味着你必须亲自承受它的痛苦；任何把这种痛苦委托出去的动作，都是 commitment 从未存在过的证据。你不能委托的是 grounding 和 rejection：亲自搞清楚用户是谁，亲自去找他们，亲自卖这个东西，亲眼看他们无视你做出来的东西，亲耳听他们当面说不，并且在没有 dashboard 可以藏身的不确定性里坐着。逃避这种痛苦最讨喜的伪装，是相信自己是 Steve Jobs 或 Elon Musk。他们的确定性从来不是“我在所有事情上都对”；而是一种很窄、很昂贵地挣来的 conviction，关于少数他们绝不妥协的事情，并且伴随着对其他所有自己搞错、必须修正的事情的残酷诚实。如果你只借走确定性，并把它涂到每一个产品判断上，那你只是在逃避那些会告诉你哪里错了的工作。

### 2. 你不可把自我表达误认为你了解用户。

可以让你的 taste 成为产品的种子，但不要让它替市场盖章。Taste 是合法的种子，是产品开始时需要的观点和 conviction。但种子是假设，不是知识。真正的假设不是“我的 taste 很好”，而是关于他人的判断：你可以代表一个真实群体；你觉得有吸引力的东西，他们也会觉得有吸引力；你想要的东西，正是他们需要的东西。自我表达不是敌人；它只有赢得用户的 endorsement，才会变成产品。这一条和下一条之间的边界很简单：用户拥有 problem；你拥有 solution。

### 3. 你不可假装自己知道用户是谁。

不知道用户是谁当然不好，但假装自己知道要糟糕得多，因为它会安静地设定你构建一切东西时的优先级，并把优先级指向一个你发明出来的用户。“开发者”不是用户。“builders”不是用户。“AI pioneers”不是用户。“Minecraft players”也不是用户。我们在 Minecraft coplayer 上学到，“Minecraft players”下面藏着 builders、PvP players、以及只想和朋友在共享世界里闲逛的人；在 Fairies 上，“white-collar workers”更多是我们希望他们成为用户，而不是他们真实看待自己的方式；在 Shortcut 上，“所有 Excel users”也慢慢收束成 finance 里以很高标准做高质量工作的人。速度让选择看起来变得可选。但它从来不是。日志告诉你 what；你饥饿的是 why。每一个宽泛标签、功能 hedge 和过早 metric，都是同一个动作：逃避具体的一手工作，然后把逃避叫作进展。

### 4. 你不可把突破误认为产品。

过去四年让这个陷阱几乎不可抵抗。模型能力跳得太远、太快，以至于一代研究者和工程师开始觉得 breakthrough 本身就是 self-evidently powerful，而 ChatGPT 好像证明了剩下的一切：一个 breakthrough 可以直接变成一个产品。这是神话。产品是把 capability 翻译成一个被满足的 need，而这个翻译本身——搞清楚这解决的是谁的问题，以及任何人会如何真实使用它——就是整个工作，不是 breakthrough 的脚注。即使 OpenAI 也没有从 breakthrough 直接跳到 product；它先 ship 了 API，然后从中学出产品。我们在 Minecraft coplayer 上兴奋于 agent 可以做出 diamond pickaxe，也兴奋于一组 agent 可以一起做出三百多种物品；这两件事都是真正的技术成就，也为我们赢得了很多注意力。但它从来不清楚，那些注意力是否反映了任何人真实拥有的 need。

### 5. 你不可把“如何使用你的产品”这个问题丢给用户。

伟大的产品有清楚的 functional affordance：用户就是能一眼看出该怎么用。真正建立在新技术上的产品，一开始通常没有这种清楚形态，而把用法说清楚是你的工作，不是用户的工作。Fairies 是一个空白聊天框，很像 ChatGPT，而我们想让用户理解它是更大的东西：一个通用 agent。我们从来没有成功说清楚那是什么意思，不管是对用户还是对自己：我们说不清用户会如何受益，它解决什么问题，甚至如何开始。Shortcut 正好相反。第一天它看起来就是一个 spreadsheet，旁边有一个 agent panel；每个用户不用我们解释，就能一眼明白这是在用 agent 自动化 spreadsheet 工作。清楚的 affordance 没有完成工作，它只是让工作可以开始。

### 6. 你不可把每个功能都看得一样重要，也不可在 launch 前继续追逐“再多一个功能”。

Focus 是说不的纪律。它不是努力做所有事情；它是决定什么不做，而这种拒绝本身就是肌肉。原因也比 effort 更深：你的功能列表就是你发送给用户的信息，告诉他们你的产品到底是什么。产品进入用户心智空间时，需要一个单一清楚的 wedge，一个他们立刻理解它是用来做什么的东西。我们在 Fairies 里 ship 过一种正好错误的功能：让 agent 改变 app 的 color theme。不需要翻 settings，只要告诉它，然后看着整个 app 改色。它感觉很好，真的很 agentic。但我说不出它为什么应该存在，不知道我们要怎么向任何人解释它，也不知道哪个用户需要它，而他们真正的问题还没有被解决。它讨好了我们，却没有对用户说任何话。

### 7. 你要被 outcome 驱动，而不是被 activity 驱动，并且要足够早地 ship，去面对 verdict。

Ship 十个 pull request 和五个功能，是 activity。它感觉像进展，但经常不是。当代码是 agent 写的，行数只是在测量它的 throughput，除此之外什么都不是。有没有人想要结果，是另一个问题，而 line count 永远回答不了。AI 可以压缩 implementation time。它不能压缩市场的 verdict。真正的 outcome，是市场用某种它不能伪造、你不能制造的东西投票：人们回来，人们带别人来，人们付钱，一个公司签约。所以，把你最不舒服的时刻——被真实用户拒绝——往左移。然后读正确的数字。不是 signup，不是掌声，不是 vanity counts：是 *return*。

### 8. 你不可在拥有一千个用户之前，就为一百万用户而构建。

你的产品是有机体，不是 spec。当你有零个用户时，搭一个能承载一百万用户的系统，感觉像 rigor。它是姿态优雅的拖延。这个陷阱更尖锐的新版本，是 coding agents 让第一天就搭最终架构感觉像是免费的，好像你可以完全跳过 exploration，直接抵达 THE correct answer。你不能。正确的系统，是随着产品找到用户而被找到的；它不是一个自以为已经看见全局的人，像画 blueprint 一样 dictating 出来的。

### 9. 你不可假设好产品会自己卖出去；你就是它的 missionary。

完成第一个版本是起跑线，不是终点线。好产品不会自己介绍自己，也不会自己让别人付钱。大多数会喜欢你所构建之物的人，永远不会知道它存在，也不会看见它能做什么，除非有人让他们看见，而那个人就是你。我们认为 Shortcut 是市场上最好的 spreadsheet agent。安静地相信这一点毫无价值；工作是让人们知道它，把它放到他们面前，直到他们看见它能做什么。证明你的 selling 起作用的，不是掌声或 signup，因为它们免费而且容易被遗忘。证明发生在 first contact 之后：人们是否回来，是否带别人来，使用是否加深，buyer 是否愿意付钱。

### 10. 你要有耐心；注意力是火花，不是燃料。

做产品需要耐心。工作是持续让它变好，一周又一周，远在第一个版本的兴奋消失之后。但注意力不是增长。注意力是火花；产品是燃料，而火花落在空油箱上，几秒钟就会灭。一个产品传播的根本原因从来不是 launch。根本原因是这个东西足够好，以至于注意力无论从哪里来，都会变成留下来、并且带别人来的人。我们在 Shortcut 身上看见过这一点：launch video 有一次真正的 viral moment，daily actives 冲上去，然后几乎以同样快的速度掉下来。那个 spike 从来不是胜利。爆发让我们被看见；只有产品让我们被留下。
