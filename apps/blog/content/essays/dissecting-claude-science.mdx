## The architecture

The most surprising part of the Claude Science is that is a very thin SwiftUI + a React App run on a bun/typescript server. When you open it via the icon, it pops out your browser and launch a website at your localhost.

![image of the open up]()

This surprises me because it feels like a vibe coded prototype instead of a refined product. But it does have some unique strength:

* it is local to your computer so it can access your local file
* it is so simple so you can easily use it cross platfrom, including in Windows via WSL
* it simplifies the developement and possibly allow developers to focus on [the core of the product](link to ship the core first) instead of doing lots of UI -- after all, its strength is the agent and the data governance and the current setup is good enough to demonstrate the power of that.

there is another reason that this is a simple typescript server running as a daemon: it needs to orchestrate multiple runtime environements. There is a dedicated, stdlib-only python interactive runtime for the operon agent, there are one or more python analytics runtime that laods the scientific and data analyisis library, there are one or more R runtime doing the same thing (the python and R runtime comes from the micromamba, which is a simplfied conda environement)

![image of the architecture component]

This setup and the orchestration requirement is much more complicated than many other agent product, because secretly shipping a hermentic R & python runtime and keep it alive and healthy via the daemon is quite a lot of engineering work. Most agentic product doesn't maintain another persistent runtime, and they usually do one-shot script running, even though sometimes that one shot running for a while. (this is where you see claude code or codex spawns lots of subprocesses)
